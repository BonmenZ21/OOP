# Задача

## Описание

Имеется таблица с произвольным количеством строк и столбцов. 
Необходимо реализовать методы произвольной выборки данных из таблицы по столбцам и по строкам, 
а также группировку данных по столбцам и по строкам.

## Предлагаемый подход к реализации

Задача интересна с точки зрения возможностей расширения и реализации - по сути, создаётся собственная мини-СУБД на Java. Можно выделить функции, которые должен выполнять модуль:

- удобное создание новых таблиц с любым количеством строк и столбцов;
- редактирование созданных таблиц;
- удаление таблиц;
- формирование произвольных отчётов для пользователя;
- отдельно, с возможностью включения и выключения, - система настройки прав доступа к данным:
  - изначально «зашитая» таблица пользователей;
  - по умолчанию два пользователя: «Админ» и «Иван Иванович»;
  - две системы настройки прав: общие и отдельные;
    - общие права: можно ли пользователю создавать/изменять/удалять таблицы (каждое право настраивается отдельно); право на отчёты доступно всем;
    - отдельные права: в каждой созданной таблице есть список пользователей и напротив них отметки (галочки) о том, что им разрешено в рамках текущей таблицы (создавать/изменять/удалять строки);
- возможность создания таблиц по шаблонам: имеется справочник шаблонов (обычный список строк) с командой «Создать на основании» для быстрого создания таблиц по шаблону;
- в рамках одной таблицы предусмотрено копирование строк; проверка на дубли не выполняется, кроме контроля уникальности ссылок на уровне приложения. При этом доступен отчёт по дублям в рамках одной таблицы и команда «Сгруппировать и заменить»: один элемент удаляется, а все связанные объекты, ссылавшиеся на него, перенаправляют ссылку на оригинальный элемент;
- создание аналога ссылок: столбец одного класса может ссылаться на элемент другого класса, иметь ссылочный тип;
- при наличии ссылок должен быть быстрый переход: двойной клик по ссылке открывает карточку связанной таблицы/элемента;
- помимо интерфейсного режима, предусмотреть SQL-подобный режим: упрощённые запросы (создание, изменение, удаление, чтение), где чтение включает "SELECT", "WHERE", "GROUP BY", "HAVING". Для разбора запросов можно использовать библиотеку (например, JSQLParser) или регулярные выражения; конкретный способ будет определён при реализации.

## Классы и атрибуты

Для решения перечисленных задач необходимо спроектировать классы и их атрибуты; для каждого поля указать назначение и связь с задачами.

Коды задач:

- **З1** - создание/редактирование/удаление таблиц;
- **З2** - выборка по строкам и столбцам;
- **З3** - группировка по строкам и столбцам;
- **З4** - произвольные отчёты;
- **З5** - права: общие и отдельные;
- **З6** - шаблоны и «создать на основании»;
- **З7** - копирование строк;
- **З8** - отчёт по дублям и «сгруппировать и заменить»;
- **З9** - ссылочные столбцы и быстрый переход;
- **З10** - SQL-подобный режим;
- **З11** - интерфейсные сценарии, карточка таблицы, выбор пользователя.

### Принципы проектирования классов

1. **Разделение метаданных и данных.**  
   "TableDefinition" описывает таблицу: имя, состав столбцов, права. "RowRecord" и "CellValue" хранят фактические данные. Это нужно для произвольного числа столбцов и для SQL-режима.

2. **Типизированное хранение ячеек.**  
   Одна ячейка - это не просто "String", а значение с типом: строка, число, дата, булево, ссылка. Это обеспечивает выборку, группировку, отчёты и ссылки.

3. **Явный реестр ссылок.**  
   Ссылку можно вычислить из "CellValue", но для быстрого перехода, контроля целостности и операции «сгруппировать и заменить» полезен отдельный "ReferenceLink".

4. **Два уровня прав.**  
   "GlobalPermission" - общие права пользователя. "TablePermission" - права в конкретной таблице. Это прямо соответствует З5.

5. **Сервисные классы как фасад.**  
   SQL-режим, отчёты, выборка и группировка не должны «лезть» в данные напрямую. Они вызывают сервисы: "DataService", "AccessService", "ReportService", "SqlQueryService" и т.д.

## Интерфейс и сценарии работы

Предлагается интерфейс с несколькими разделами и сценариями. 
Система авторизации не создаётся: при запуске в специальном окне просто выбирается текущий пользователь. 
Далее возможны два варианта.

1. Вход в качестве администратора. Доступны два основных раздела:

   - **Администрирование**:
     - таблица «Пользователи» - для настройки прав;
     - «Шаблоны» - для контроля шаблонов;
     - изначально «зашитый» отчёт с правами пользователей по конкретным объектам;
     - SQL-режим.

   - **База данных**:
     - несколько гиперссылок, две группы:
       - «Создать» и «Создать по шаблону» (с окном выбора шаблона);
       - названия уже созданных таблиц; при нажатии пользователь переходит в карточку таблицы.

2. **Карточка таблицы**:
   - изначально отображаются только строки;
   - двойной клик по строке позволяет менять значения её атрибутов;
   - доступно копирование;
   - вверху расположены команды «Отчёт по дублям» и «Настройка», где контролируются название таблицы, её состав, права и т.д.
